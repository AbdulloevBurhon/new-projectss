# «Цех» для Windows

Из корня репозитория соберите EXE на Windows x64:

```powershell
volta run --node 22.22.3 npm ci
volta run --node 22.22.3 npm run desktop:build --workspace @obshaya/tsekh
```

Версия берётся из `tsekh/package.json`. Файл `Tsekh-<версия>-Windows-x64.exe` появится в `tsekh/release/`. Для запуска нужен Microsoft Edge WebView2 Runtime. Данные и активация хранятся в профиле `%LOCALAPPDATA%\Tsekh-4\profile`.

Для следующего выпуска увеличьте версию в `tsekh/package.json`, обновите lock-файл и соберите EXE. В админке откройте «Обновления», выберите направление «Цех», укажите ту же версию и загрузите файл. В настольном «Цехе» откройте «Настройки» → «Проверить обновление» → «Установить и перезапустить». EXE должен находиться в папке, доступной пользователю на запись. После входа новая версия сообщает об установке админке.

Для архивов выберите две папки и задайте интервал `0 ч 1 мин`. С включённой галочкой «Копировать в облако» каждый цикл обновляет `tsekh-backup.json` в двух папках и один архив устройства в админке. Файл, удалённый вручную, создаётся заново при следующем цикле. Копии создаются, пока «Цех» открыт и выполнен вход. Облачная копия требует доступного API и интернета.

Для облачной архивации обновите Worker из этой ветки. Маршрут `PUT /api/client/archives/latest` использует существующие D1 и R2. Ручной экспорт с облачной копией сохраняет отдельный архив.

## Локальный API и проверка

[Главная карта проекта](../STRUCTURE.md) · [Данные и окружения](../docs/data-and-runtime.md)

EXE открывает интерфейс через WebView2. `WorkshopApi.cs` принимает локальные запросы, а `desktop/modules/` содержит обработчики архива, товаров, поступлений, сотрудников и обновлений. Запросы продаж загружаются из тех же JSON-файлов SQL, что использует Nuxt. Рабочая SQLite находится в `%LOCALAPPDATA%/Tsekh-4/data/tsekh.sqlite`.

Раздел [«Ревизия»](../app/features/revision/INSTRUCTION.md) использует обработчик `desktop/modules/revision/StockRevision.cs` и общие с Nuxt запросы SQLite. Черновики и итоги входят в JSON-архив.

Открытый EXE использует общую с Nuxt схему локальной очереди Telegram. Интервал приходит из лицензии. При восстановлении сети EXE отправляет сохранённые комплекты за три последних календарных дня после проверки интервала. Для работы очереди нужен EXE с поддержкой нового маршрута Worker. Подробнее в [инструкции Telegram](../docs/features/telegram.md).

Кнопка «Открыть бота в Telegram» передаёт ссылку подтверждения `https://t.me/…?start=…` браузеру Windows по умолчанию. WebView2 продолжает обслуживать внутренние страницы «Цеха».

После аварийного завершения процесса отрисовки WebView2 «Цех» один раз перезагружает текущую страницу. Повторные сбои в течение 30 секунд не запускают цикл перезагрузок.

Настройки чекового принтера хранятся в `data/receipt-printer.json` рядом с локальной SQLite. USB-печать идёт через очередь и драйвер Windows. LAN-печать отправляет растровый чек по TCP с командами ESC/POS. Перед выдачей принтера проверь пробный чек на фактической бумаге 58 или 80 мм.

В тестовой сборке, где облачный API направлен на `http://127.0.0.1:`, `TSEKH4_TEST_PROFILE` позволяет использовать отдельный корень профиля. Для расхождений между браузером и EXE сравни метод, путь, ответ и изменение SQLite в каждом окружении.
