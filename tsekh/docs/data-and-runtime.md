# Данные и окружения

[Главная карта](../STRUCTURE.md)

| Где | Какие данные и запросы |
| --- | --- |
| SQLite Nuxt | Файл `.data/tsekh.sqlite` относительно рабочего каталога Nuxt. Обычно `tsekh/.data/tsekh.sqlite`. Счета и операции, товары, склады, поступления, продажи, строки чеков, сотрудники, локальные сеансы, клиенты и погашения их долгов. Подключение в [`accounts.database.ts`](../server/database/accounts/accounts.database.ts). |
| SQLite Windows | `%LOCALAPPDATA%/Tsekh-4/data/tsekh.sqlite` для обычного профиля. Локальные маршруты обслуживает EXE через [`WorkshopApi.cs`](../desktop/WorkshopApi.cs). Смотри [описание Windows](../desktop/README.md). |
| Браузер или WebView | Техкарты, локальные настройки интерфейса, кеш состояния лицензии и отпечаток ПИН для входа офлайн. Техкарты экспортируются в JSON с прикладными данными. |
| Cloudflare D1 | Активация, лицензии, данные админки, сообщения, сведения об обновлениях и состояние Telegram. Запросы Worker отделены от локального API Nuxt. |
| Cloudflare R2 | Облачные архивы. Плановая отправка обновляет последнюю копию установки, ручная создаёт отдельный архив. |

- Nuxt использует `server/api/`, Windows принимает те же прикладные маршруты через диспетчер C#. Оба используют SQL из `server/database/sales/*.json`. При проверке расхождения сразу установи, какой обработчик ответил.
- В счетах баланс хранится в сомах. В продаже поля `sales.total`, `sales.paid`, `sales.discount` и `sale_lines.amount` хранятся в сотых долях сома. Цена единицы товара хранится в сомах. Проверь единицы перед изменением расчёта или вывода.
- Остатки рассчитываются из складских движений, проведённых поступлений и продаж. Pending-поступление и проведённое поступление имеют разные правила изменения.
- Черновики и результаты [ревизий](../app/features/revision/INSTRUCTION.md) хранятся в `stock_revisions` и `stock_revision_lines`. Итоговые корректировки входят в `stock_movements`.
- JSON-архив объединяет прикладные таблицы SQLite и данные, отобранные из хранилища браузера. Архив содержит хеши ПИН сотрудников, а активные сеансы сотрудников и облачные лицензии живут отдельно. Для проверки импорта используй тестовый профиль и резервную копию.
- Облачный ПИН установки и сеанс сотрудника проверяются в разных местах. Для 401 облачного API начни с лицензии и заголовков клиента. Для локального 403 начни с прав сотрудника.
