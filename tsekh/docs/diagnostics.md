# Диагностика ошибок

[Главная карта](../STRUCTURE.md)

1. Зафиксируй экран, действие, ожидаемый результат и фактическое поведение. Запиши, где воспроизводится ошибка (Nuxt или EXE), под кем выполнен вход и есть ли сеть.
2. Повтори один раз. В Network запиши путь, метод, статус и безопасные поля ответа. Для складских и денежных ошибок запиши идентификаторы операции, товара, склада и счёта. Убирай из отчёта ПИН, токены, заголовки авторизации и содержимое архива.
3. По таблице найди ближайшую точку проверки. Сверь ответ API с экраном. Затем проверь состояние в тестовой базе, используя те же параметры и единицы измерения.
4. После исправления повтори исходный сценарий, проверь соседние разделы и ошибочный вариант. Укажи, в каком окружении это проверено.

| Симптом | Первая проверка | Где смотреть дальше |
| --- | --- | --- |
| После входа открылся экран активации или пропало меню | Статус лицензии, маршрут, режим администратора или сотрудника | [Доступ](../app/features/access/instructions/README.md), [Главная](../app/features/home/instructions/README.md) |
| `messages?peek=1` отвечает 401 или запрос не проходит без сети | Отдельно проверь сетевую ошибку и срок облачного ПИН | [Доступ и поддержка](../app/features/access/instructions/README.md) |
| 403 или пропало действие | Права раздела и действия, локальный сеанс сотрудника | [Сотрудники](../app/features/workers/INSTRUCTION.md) |
| Поступление есть в истории, а остаток не меняется | Статус записи и время проводки, затем товар и склад | [Склад](../app/features/warehouse/INSTRUCTION.md) |
| Списание в кассе не совпало с поступлением | Счёт и статус проводки, закупочная цена за базовую единицу, движение в деталях обоих счетов | [Счета](../app/features/accounts/instructions/README.md), [Склад](../app/features/warehouse/INSTRUCTION.md) |
| Неверные граммы, штуки или сумма чека | Единица продажи, коэффициент упаковки и цена за выбранную единицу | [Продажи](../app/features/sales/instructions/README.md) |
| Продажа отсутствует в отчёте или у сотрудника | Сохранённый чек, фильтры, идентификатор сотрудника | [Отчёты](features/reports.md), [Сотрудники](../app/features/workers/INSTRUCTION.md) |
| Не сходится долг клиента | Оплата и сумма чека, привязка к клиенту | [Клиенты](../app/features/clients/instructions/README.md) |
| Копия не появилась в облаке | Статусы назначения, лицензия, ручная или плановая отправка | [Настройки](../app/features/settings/instructions/README.md), [Админка и облако](features/admin.md) |
| Telegram не прислал отчёт или архив | Подтверждение контакта, одобрение, сеть, интервал и статус доставки | [Telegram](features/telegram.md) |
| Работает в Nuxt, но сломано в EXE | Повтори тот же HTTP-контракт в Windows, сравни обработчики и SQL | [Данные и окружения](data-and-runtime.md) |

## Git остановил обновление на SQLite

Если `git pull --ff-only` остановился на `tsekh/.data/tsekh.sqlite-wal`, сравни `git status --short` и `git ls-files -- tsekh/.data/`. Файлы SQLite входят в текущую ветку Git, а запущенное приложение записывает в WAL. Перед обновлением останови приложение и сохрани рабочие данные вне репозитория. Для независимой проверки новой версии используй отдельную рабочую копию и тестовую базу. Сброс, удаление или откат файлов рабочей SQLite может потерять операции пользователя.
