# Telegram — отчёт и резервная копия

[Главная карта](../../STRUCTURE.md)

1. На `/settings` введи номер с кодом страны. Открой выданную ссылку бота и поделись своим контактом. В Windows ссылка открывается в системном браузере. После совпадения номера одобри доставку в «Цехе».
2. Оператор задаёт интервал в админке в разделе «Клиенты» → «Редактировать клиента». В «Цехе» поле интервала доступно для просмотра. Ноль отключает расписание. После одобрения первой отправки «Цех» автоматически подключает устройство и получает интервал. Если номер одобрен ранее, для первого подключения обновлённого устройства может понадобиться один вход под постоянным ПИН.
3. Бот отправляет бэкап файлом JSON, затем два текстовых отчёта прямо в чат. JSON предназначен для импорта в «Цех» и содержит снимок данных SQLite и техкарты из хранилища приложения. Первый отчёт содержит продажи за всё время, сравнение сегодня со вчера и долг. Второй содержит остатки меньше 50 шт. для штучных и меньше 50 кг для весовых товаров. Количество показывается в единице складского остатка, например «Картошка — 8 кг». Граммы и содержимое упаковок пересчитываются в килограммы или штуки для проверки порога. Остатки суммируются по товару на каждом складе с учётом единицы измерения. Ровно 50 шт. или 50 кг в отчёт не попадает. Длинные отчёты разбиваются на несколько сообщений. Снижение остатка само по себе не запускает доставку. Даты берутся по местному времени приложения.

4. Пока «Цех» открыт под администратором или сотрудником, локальная SQLite сохраняет снимки по полученному интервалу даже без интернета. За день хранится последний ожидающий комплект. Если отправка уже началась, её комплект хранится отдельно до подтверждения. Очередь ограничена сегодняшним днём и двумя предыдущими календарными днями устройства. После восстановления связи «Цех» получает актуальный интервал и отправляет сохранённые комплекты. При отключённом расписании очередь очищается. Telegram Worker запоминает подтверждённые сообщения каждого комплекта и продолжает с первой неподтверждённой части.

Расписание требует версии «Цеха» и Worker с поддержкой очереди, а также миграций D1 0009–0011. Ключ привязан к подтверждённому чату. Ключ, настройки расписания и очередь хранятся локально вне пользовательского архива. Сотруднику доступен запуск очереди. Файл бэкапа и ключ в ответ локального API очереди не включаются.

| Участок | Файлы |
| --- | --- |
| Карточка и подтверждение | [`TelegramDeliveryCard.vue`](../../app/features/settings/components/TelegramDeliveryCard.vue), `app/features/settings/composables/useTelegramDelivery.ts` |
| Расписание и запросы | [`useTelegramSchedule.ts`](../../app/features/settings/composables/useTelegramSchedule.ts), `endpoints/settings/telegram/telegram.service.ts`, `server/services/telegram/`, `desktop/modules/archive/` |
| Снимок локальных данных | `GET /api/data-archive?reports=telegram-text&backup=1`. Текст и данные SQLite берутся в одной транзакции. |
| Бот и результат доставки | [`telegram.ts`](../../../cloudflare/worker/src/handlers/client/telegram.ts) и соседняя папка `telegram/`, миграции D1 0007–0011 |

Для «Маршрут не найден» сначала установи, какой API вернул 404, и проверь нужный маршрут в версии Worker или Windows. Для отказа проверь постоянный ПИН, разрешение на облачные архивы, подтверждённый номер и одобрение. При частичной или неопределённой отправке проверь журнал состояния доставки до ручного повтора.

Проверь согласованный тестовый чат, сравнение двух дней, читаемость архива, четыре календарных дня без сети и повтор после частичного сбоя. Настройка секретов и webhook описана в [документации Worker](../../../cloudflare/worker/README.md).
