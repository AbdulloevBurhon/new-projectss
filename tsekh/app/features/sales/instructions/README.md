# Продажи

[Главная карта](../../../../STRUCTURE.md)

- `/sales` подключает [`SalesScreen.vue`](../components/SalesScreen.vue). Каталог, фильтры, состояние корзины и её ширина находятся в `SalesScreen.vue`. Содержимое корзины в [`SaleCart.vue`](../components/SaleCart.vue), оплата в [`SalePayment.vue`](../components/SalePayment.vue). Файлы `composables/useSalesScreen.ts` и `data/sale-catalog.ts` относятся к старому макету.
- Запросы в `endpoints/sales/service.ts`. Каталог использует `GET /api/sales/catalog`. Режим `setup` выдаёт склады и счета, `page` — до 15 товаров выбранного склада, `barcode` — точные совпадения по штрихкоду. Следующая страница загружается при прокрутке до конца текущей. Поиск по названию начинается с первой страницы. Штрихкод проверяется по всему выбранному складу. Повторный скан использует найденную позицию до смены склада или окончания продажи. Запрос `POST /api/sales/checkout` обрабатывает `server/api/sales/[...path].ts` через [`sales.service.ts`](../../../../server/services/sales/sales.service.ts). SQL в `server/database/sales/` также используется Windows.
- Задайте штрихкод в товаре. На странице «Продажа» наберите код и нажмите Enter или сканируйте в режиме клавиатуры с Enter после кода. Набранный код виден под поиском. Пока курсор находится в поле ввода, списке или открытом диалоге, клавиши работают в этом элементе. Щёлкните вне поля, чтобы вернуться к сканированию. Проверка кода идёт по наличию на выбранном складе, учитывает ведущие нули и работает при любом фильтре по названию. При отсутствии совпадения появляется окно «Товар не найден» с введённым кодом. Вводом управляет общий [`BarcodeScanner.vue`](../../../components/barcode/BarcodeScanner.vue), добавлением в корзину — [`scanBarcode.ts`](../scanBarcode.ts).
- Один скан добавляет одну складскую единицу, например 1 кг или 1 упаковку. Повторный скан увеличивает количество по каталожной цене. Если нужен дробный объём, выберите позицию в списке и укажите количество в корзине. При недостаточном остатке или нескольких совпадениях появится сообщение.
- При оплате продавец и роль заполняются автоматически для отчётов. Для сотрудника используются данные локального сеанса, для администратора — «Админ» и «Администратор».
- Продажа, строки чека, складское списание, привязка сотрудника и зачисление фактически оплаченной суммы выполняются вместе. Повтор отправки использует идентификатор операции. Разница между итогом и оплатой учитывается как долг при привязке к клиенту.
- При складском списании позиции первыми уменьшаются партии с ближайшим сроком годности. Остаток по партиям виден на вкладке «Срок годности» в «Складах».
- Для товара в кг цена за кг и количество в кг. Например, `0,5 кг × 6 сом/кг = 3 сома`. Для упаковки с содержимым проверь единицу продажи и пересчёт из штук в остаток упаковок. Чек формирует `printReceipt.ts` через `GET /api/sales/receipt/:id/details`. Сотрудник с правом продажи может печатать свои чеки. Для просмотра чужих чеков нужен доступ к отчётам. Назначенные склады и счета ограничивают каталог, оплату и выдачу чеков. Для кассира без права менять склад и счёт сервер выбирает первые доступные ему позиции.
- После изменения оплаты проверь остаток, деньги на счёте, чек в [отчётах](../../../../docs/features/reports.md), долг клиента и отчёт сотрудника. Также проверь отказ при нехватке товара и повтор запроса с тем же идентификатором.
- Печать после продажи и повторная печать из отчётов используют вкладку «Настройки → Принтер». На чеке есть название магазина и, при наличии, имя клиента. Если принтер недоступен, сохранённая продажа остаётся в отчётах.
